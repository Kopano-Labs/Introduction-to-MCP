Remote config — four steps

Sequential unblockers. Replace OWNER/REPO, FULLSHA, and remote name with your fork if needed.

1 — List remotes + URLs
shell
git remote -v

Expect your push target to be the fork where you open PRs (e.g. RobynAwesome/Introduction-to-MCP), not necessarily Kopano-Labs/….

2 — Branch + upstream tracking
shell
git branch -vv git status -sb
3 — Push (unblocks SHA / CI / PR receipts)
Example (only if origin is already your fork):
shell
git push -u origin codex/kc-sovereign-gui-full-dev

If origin is upstream org, use your fork remote instead:

shell
git push -u fork HEAD
4 — Confirm commit on GitHub API (after push)

Use full 40-character SHA when possible; short prefixes can be ambiguous.

shell
curl -s "https://api.github.com/repos/OWNER/REPO/commits/4ec8344" | head -c 500 # Prefer full 40-char SHA once you have it: # curl -s "https://api.github.com/repos/OWNER/REPO/commits/FULLSHA40..." | head -c 500 # Browse (same short SHA example): # https://github.com/OWNER/REPO/commit/4ec8344

Private repos often return 404 to anonymous API — use an authenticated client or the web UI.

SHA trace

Three views: local object, remote ref, fork delta.

shell
git log --oneline -15 git show --stat HEAD git cat-file -t HEAD git rev-parse HEAD

Remote verify = git ls-remote (refs on the server) plus GitHub API (commit object) after push.

shell · ls-remote
git ls-remote origin "refs/heads/*" git ls-remote origin HEAD git ls-remote origin "refs/heads/codex/kc-sovereign-gui-full-dev"
shell · API (replace OWNER/REPO)
curl -s "https://api.github.com/repos/OWNER/REPO/commits/4ec8344" | head -c 500 curl -s "https://api.github.com/repos/OWNER/REPO/commits/$(git rev-parse HEAD)" | head -c 500

Short SHA 4ec8344 is an example prefix; prefer the full 40-character hash for receipts. Private repos may return 404 without auth.

shell
git fetch origin git log --oneline --graph --decorate -20 --all git diff origin/main...HEAD --name-only

Replace origin/main with your default branch if needed. Expect docs/swarm-ops/* in the diff when swarm doctrine is your delta.

.gitignore audit

Ignored vs tracked
shell
git check-ignore -v Schematics/ git check-ignore -v docs/swarm-ops/SWARM_OPERATIONS.md || echo "(no output on second = not ignored)"
Inventory ignored trees
shell
git ls-files --others --ignored --exclude-standard --directory | head -25
Optional pre-commit: block tracked files inside ignored paths
bash · install to .git/hooks/pre-commit
#!/bin/sh git ls-files | while IFS= read -r f; do if git check-ignore -q "$f" 2>/dev/null; then echo "tracked but ignored: $f"; exit 1 fi done

On Windows without bash, skip or use WSL/Git Bash for the same loop.
