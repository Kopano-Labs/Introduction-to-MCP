# PKA — Bapedi Cultural Game Hub

## Overview

Use this skill when implementing or reviewing the Mark 1 Hub Framework case study for the Bapedi UCT Society cultural Game Hub.

Mark 1 is **not** a proof that a bubble-shooter game works. Bubble is the first replaceable mechanical adapter used to prove that the Hub Framework survives when the individual game changes.

The governing flow is:

```text
Cultural Data Hub
  -> governed state contracts
  -> Telemetry AI event stream
  -> parser
  -> PKA
  -> minimal Markdown state pass
  -> Identic AI boundary
  -> adaptive action candidate
  -> KPGS governance
  -> APWA shell
  -> player
  -> telemetry loop
```

## Instructions

1. Treat Telemetry AI as an independent evidence flow. Do not reduce it to analytics or personalization.
2. Record machine/world observations before semantic interpretation when available: session state, network/offline state, PWA state, orientation, touch patterns, game transitions, progression, outcomes, sticker/reward interactions, return behaviour, and next-game selection.
3. Parse raw telemetry into a smaller candidate state. The parser may count and normalize; it must not declare a permanent human trait or cultural identity.
4. Apply PKA to candidate claims. Preserve `MAYBE` whenever evidence, time coverage, or governance is insufficient.
5. Pass only the minimum governed state to Identic AI. Prefer a small `.md` membrane over dumping the raw telemetry stream into model context.
6. Identic AI may propose an adaptive action. It does not directly mutate the GUI.
7. State changes must pass a governed contract transition: `from_state -> precondition -> action -> to_state -> receipt`.
8. Emit Memory Receipts only for consequential approved/applied transitions. Raw telemetry remains in the Telemetry AI evidence lane.
9. Use non-cultural placeholder assets until the Bapedi UCT Society/domain authorities approve cultural entities, meanings, language variants, symbols, stickers, or gamification boundaries.
10. The graduation test is a second game adapter using the same Hub contracts without changing the Hub core.

## PKA primitive

```text
X + Y = MAYBE
```

- `X` = partial/changeable observed state.
- `Y` = known/versioned governance state.
- `MAYBE` = legitimate non-closure.

Do not promote `MAYBE` to fact because a model can complete the pattern.

## Mark 1 acceptance gates

- one telemetry contract across games
- parser produces governed candidate state
- insufficient evidence remains `MAYBE`
- temporary adaptations are bounded and reversible
- permanent personality/cultural identity claims are prohibited from gameplay telemetry
- APWA state changes require approved transitions
- consequential transitions emit receipts
- offline -> online continuity survives
- Bubble adapter is replaceable
- a second adapter runs without Hub-core modification

## Example

Telemetry across two sessions shows repeated traversal of the `word` category.

Invalid conclusion:

```text
player permanently prefers word games
```

Valid bounded candidate after the configured evidence gate:

```text
surface the word category in the next session only
```

The second statement is an adaptive action candidate, not a personality claim. Future telemetry may reverse it.

## Constraints

- Do not invent Bapedi cultural facts.
- Do not treat game telemetry as proof of a person's culture, personality, religion, or permanent preference.
- Do not make blockchain, token, wallet, or Web3 infrastructure a Mark 1 dependency.
- Do not let one game define the Hub architecture.
- Do not bypass the governance transition layer to mutate player-facing state.
- Do not store raw telemetry inside the minimal Identic AI pass.
- Do not claim a PKA rule is a formal mathematical theorem unless its mathematical proof obligations are separately satisfied.
